# 零基础知识手册

这是为本项目编写的中文解释，帮助建立直觉；精确定义和实现细节通过 [资料导航](resources.md) 回到官方文档和作者资料。每节先掌握“能够解释什么”，遇到公式时先核对单位，再代入一个例子。

## 1. 这个系统在做什么

相机把光投影到二维像素阵列。IMU 的加速度计和陀螺仪分别提供比力、角速度读数。算法把多个时刻的观测联系起来，估计运动和结构。传感器之间必须知道空间关系和时间关系，观测才可以放进同一个计算问题。

一个小实验就能看出困难：分别用左右眼看近处的手指，它相对远处背景的位置发生变化。距离线索来自两个视点的对应关系。如果目标在两次观察之间移动，这个变化就同时包含视角变化和时间变化。

学习链路：程序和单位 → 图像和坐标 → 投影与标定 → IMU 与时钟 → 多视角和估计 → 复现与评测。每一层都要保留输入、处理步骤和输出。

## 2. 程序、文件与数组

程序是一组按顺序执行的明确指令。变量保存值，条件选择分支，循环重复操作，函数把可重复的步骤命名。CSV 是每行一条记录、字段用分隔符分开的文本；JSON 适合保存带名称和层次的配置。

数组是按索引访问的一组值。灰度图像通常可表示为形状 `(height, width)` 的二维数组；三通道图像通常是 `(height, width, 3)`。数学中常写像素 `(u,v)`，数组却常用 `[v,u]`，两者不能随手交换。

OpenCV 常见彩色输入采用 BGR 通道顺序；“三通道”本身不能说明 RGB 还是 BGR。读入图像后记录形状、类型、颜色顺序。整数 8 位灰度常用 0–255 表示亮度等级，但像素值不是物理照度的直接测量。

练习：一张 640×480 图像的中心大约在哪里？数组访问时哪个索引先写？缩放为原来一半后，原像素 `(200,100)` 大约到哪里？答案：中心约 `(320,240)`；行即 `v` 在前；约 `(100,50)`，精确像素中心映射依赖缩放约定。

## 3. 单位、帧率与数据量

| 名称 | 含义 | 例子 |
|---|---|---|
| s / ms / μs / ns | 秒 / 毫秒 / 微秒 / 纳秒 | 1 s = 1000 ms = 10⁹ ns |
| fps / Hz | 每秒帧数 / 每秒周期数 | 30 fps 的平均间隔为 1/30 s |
| B / bit | 字节 / 比特 | 1 B = 8 bit |
| MB / MiB | 十进制 / 二进制数据量 | 1 MB = 10⁶ B；1 MiB = 2²⁰ B |
| px / m / rad | 像素 / 米 / 弧度 | 180° = π rad |

未压缩图像量的简化计算：`相机数 × 宽 × 高 × 每像素字节 × 帧率`。两台 1280×720、8 位灰度、30 fps 相机得到 55,296,000 B/s，即 55.296 MB/s，约 52.734 MiB/s；连续十分钟约 33.178 GB。三通道 8 位图像再乘 3。

这是教学估算，不包含行填充、数据头、缓存和文件开销，也不适用于直接预测 MJPEG 等压缩流大小。是否丢帧要看实际日志。程序请求 30 fps，不代表设备始终交付 30 fps。

## 4. 数学先学到什么程度

| 阶段 | 必会内容 | 暂缓内容 | 自测 |
|---|---|---|---|
| A | 四则运算、比例、单位换算、均值 | 复杂微积分 | 把帧率换成时间间隔 |
| B | 向量、矩阵乘法、三角函数直觉、逆变换 | 李群完整推导 | 画出坐标系并变换一个点 |
| C | 标准差、积分是累加、偏置误差 | 随机过程严格证明 | 解释偏置为何持续积累 |
| D | 导数是变化率、最小二乘、协方差直觉 | EKF/MSCKF 全部推导 | 比较加异常值前后的直线拟合 |
| E/F | 误差指标、统计样本与复现实验 | 新估计器证明 | 区分指标改善与实验条件改变 |

每个新数学对象先写“输入是什么、输出是什么、单位是什么”，再写符号。课程可拉长，不用提前补完一整套大学数学。

## 5. 坐标系和外参：先写方向

同一个物理点，在相机和 IMU 坐标系中有不同坐标。本文使用约定：`T_A_B` 把 B 坐标表达转换成 A 坐标表达。

```text
p_A = R_AB p_B + t_AB
p_B = R_AB^T (p_A - t_AB)
T_A_B 的逆 = T_B_A
T_A_C = T_A_B T_B_C
```

`R_AB` 是旋转矩阵，`t_AB` 是 B 原点在 A 中的位置。必须同时说明轴方向、长度单位和列向量约定。别人的文件可能使用相反命名，读配置时先确认，不能只看字母相同。

二维例子：点 `(1,0)` 逆时针旋转 90° 得 `(0,1)`，再沿 x 平移 1 得 `(1,1)`。如果先平移得到 `(2,0)`，再旋转得到 `(0,2)`。所以变换次序通常不能交换。

## 6. 投影、内参与畸变

理想针孔模型将相机坐标系中的三维点映到像素：

```text
u = fx × X/Z + cx
v = fy × Y/Z + cy
K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]
```

这里简化为零斜切模型；`X,Y,Z` 同一长度单位，`Z > 0`，`fx,fy,cx,cy` 单位是像素。相机实体镜头标注的毫米焦距不能直接当作像素焦距。

例：`fx=600 px, X=0.2 m, Z=2 m, cx=320 px`，得到 `u=380 px`。深度变成 4 m 时得到 350 px。实际镜头还有畸变，需要匹配适当模型。宽角或鱼眼镜头不宜直接套用普通针孔畸变模型。

标定是从已知结构的观测估计参数。我们的棋盘是 **8×5 内角点、9×6 方格**，设计格长 20 mm；打印后必须实测。分辨率、裁剪、变焦、对焦或镜头安装发生变化，都需要重新检查内参适用性。

重投影误差是“预测角点与检测角点的像素差”。本方案采用每图 `sqrt(mean(dx²+dy²))`，明确是每个二维点的欧氏误差 RMS。不要把逐坐标 RMSE 与逐点 RMS 混用。训练误差低只说明拟合了训练观测；用留出图估计每张棋盘姿态后重投影，仍只是额外一致性检查，不能称为独立测得了物理精度。

## 7. 快门、曝光与同步

曝光是一段时间，而不是理想瞬间。曝光越长，运动模糊可能越明显。全局快门和卷帘快门的区别涉及各像素行曝光时间：卷帘情况下，整幅图像没有一个能代表所有行的精确共同曝光时刻。

标注图像时间时需要说明它指曝光开始、中心、结束，还是主机读到数据。对全局曝光可约定中心时刻；对卷帘还需行时间模型和参考行约定。`camera.read()` 返回前后打的时间戳只是应用观察到的主机事件。

```text
相机时钟：开始曝光 ---- 结束曝光 -- 读出 -- 传输
主机时钟：                                  收到/取出图像
IMU 时钟：采样 -- 寄存器/FIFO -- 软件读取 -- 串口传输
主机时钟：                                             收到字节
```

“两路数据都用 USB”不等于共享采样时钟。不同设备的计时原点与速率不同，不能直接相减；同一主机收到的时间又包含缓存与传输延迟。硬件触发、时钟同步、时间偏移估计各解决不同部分，需要实验验证。

小角度、近图像中心、近似纯旋转条件下，像素偏差可粗估为 `fx × 角速度 × 时间偏差`。`800 px × 2 rad/s × 0.002 s = 3.2 px`。这只用于建立量级直觉，不是任意场景的误差上限。

## 8. IMU 为什么静止也有读数

加速度计测的是比力。一个常用模型为：

```text
f_body = R_world_body^T (a_world - g_world) + bias + noise
```

`R_world_body` 将机体系向量转到世界系；`g_world` 为重力加速度向量。静止放置时，读数模长通常约为 9.81 m/s²（1 g），各轴正负由坐标约定决定。陀螺仪静止读数应接近零，但存在偏置与噪声。

官方库示例的单位需要逐项核对；若加速度输出为 g，则乘标准重力 `9.80665` 转为 m/s²；角速度 deg/s 乘 `π/180` 转为 rad/s。不要只改 CSV 列名却忘了换算数值。

偏置是系统性偏移，噪声是随机波动，漂移是积分后误差逐渐累积的现象。假设陀螺恒定偏置 0.05°/s，60 秒积分就产生 3° 偏差。假设未补偿加速度偏置 0.1 m/s²，10 秒双重积分误差为 `0.5×0.1×10²=5 m`。这些是简化教学模型，不是所推荐开发板的实测性能。

六轴 IMU 本身不提供长期稳定绝对偏航和位置。重力方向可帮助估计缓慢运动时的倾斜；快速平移时，比力包含运动分量，不能把它全当作重力。

## 9. 多视角、特征和深度

特征是图像中便于重复识别的位置及描述。匹配把两张图中的候选对应关系连接起来。重复纹理、反光、模糊和低纹理会产生错误；匹配点多并不保证几何正确。RANSAC 用多个小样本提出模型并检查一致性，仍需合理阈值和场景假设。

对于已标定并校正为平行模型的双目，满足相应主点约定时：`Z = f × B / d`。`f` 为像素焦距，`B` 为米制基线，`d` 为同名点水平视差。例：`600 px × 0.06 m / 30 px = 1.2 m`。视差为 15 px 时深度为 2.4 m；视差趋近零时深度很不稳定。

普通摄像头可做静态棋盘的双目标定练习：在每一对采集期间保持棋盘和相机不动。这个条件绕开了场景变化，不证明动态同步能力。公式也不能直接用于未经校正的任意两张图像。

## 10. 从最小二乘到 VIO

假设拟合直线 `y = ax+b`，每个观测的预测差叫残差，最小二乘寻找让残差平方和最小的参数。异常值因为被平方可能有很大影响。权重表示对不同观测的信任，协方差描述不确定性及变量之间的相关，雅可比描述预测对参数小变化的敏感性。

VIO 要估计的位置、速度、姿态和 IMU 偏置都是未知量；图像与 IMU 提供约束。估计器利用运动模型传播状态，再用观测修正。理解这张数据流图后，再看 OpenVINS 的状态估计细节。

| 名词 | 主要问题 | 初学者容易混淆的地方 |
|---|---|---|
| VO | 仅视觉估计相对运动 | 单目一般存在尺度不确定性 |
| VIO | 视觉与惯性联合估计运动 | 需要正确的时间、空间和噪声配置；并非插上 IMU 就能工作 |
| SLAM | 同时定位和建图，常包括长期一致性机制 | 回环和地图管理不等同于短时 VIO |
| 3D 重建 | 恢复场景几何或外观 | 看起来漂亮不自动代表定位或尺寸准确 |

## 11. 评测：先说明比较条件

绝对轨迹误差 APE/ATE 描述轨迹相对参考的偏差；相对位姿误差 RPE 描述某个时间/距离间隔的运动误差。要记录时间关联容差、坐标对齐、单位、参考来源、成功跟踪区间和失败次数。

有公制尺度的 VIO 通常报告刚体 SE(3) 对齐的结果，不应悄悄用尺度校正隐藏尺度误差。单目 VO 若使用 Sim(3) 对齐，应明确写出。比较算法时要保持同一数据、配置范围和评价协议。

重复两次标定结果接近叫重复性好，未必准确；没有真值时可以报告一致性和观察到的问题，不要用它冒充绝对误差。

## 12. 术语速查与退出题

| 英文 | 中文 | 你要能说出的解释 |
|---|---|---|
| intrinsic / extrinsic | 内参 / 外参 | 成像模型内部参数 / 坐标系之间的关系 |
| bias / noise | 偏置 / 噪声 | 系统偏移 / 随机波动 |
| timestamp / clock domain | 时间戳 / 时钟域 | 哪个事件的时间 / 哪一套计时基准 |
| baseline / disparity | 基线 / 视差 | 两视点距离 / 对应像素的位置差 |
| residual / covariance | 残差 / 协方差 | 观测与预测差 / 不确定性与相关性 |
| calibration / validation | 标定 / 验证 | 估计参数 / 用额外证据检查参数与流程 |

每完成六周，随机挑三题闭卷解释：同一张图缩小后内参如何变化？为何两个 USB 设备不能直接做曝光同步结论？IMU 静止为何不是三轴零？训练误差降低代表什么、不代表什么？六轴 IMU 缺少什么长期约束？没有真值时哪些结论仍可以诚实报告？答不清就回到对应实验，不急着读更复杂论文。
