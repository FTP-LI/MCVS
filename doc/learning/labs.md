# 实验任务书

每个实验都保留原始输入和一份简短报告。数据来源必须写清：`自采 / 公开数据 / 模拟 / 他人估计结果`。阶段不足时可完成预备任务，但不自动通过需要真实操作的关卡。每周核心实验约 2–3 小时；复杂实验跨周完成，排错超过 2 小时就记录问题并转预备任务。

建议个人记录目录如下；本仓库不预先填造数据：

```text
MCVS-study/
  week01/notes.md
  lab04_calibration/raw/       # 原始图像
  lab04_calibration/splits/    # train / holdout 文件列表
  lab04_calibration/results/   # 参数、图表、日志
  lab04_calibration/report.md
  environment.txt
```

## 环境分步准备

第 1 周只用标准库示例。第 4–5 周需要数组和图像时，在项目目录用 Python 3 创建自己的虚拟环境，不要求管理员权限或修改执行策略：

```powershell
py -m venv .venv-learning
.\.venv-learning\Scripts\python.exe -m pip install numpy opencv-python matplotlib pyserial
.\.venv-learning\Scripts\python.exe -m pip freeze
```

这里的 NumPy 用于数组，OpenCV 用于图像，Matplotlib 用于画图，pyserial 到 IMU 阶段再使用也可以。记录安装日期和实际版本，遇到包不支持当前 Python 时先核对官方支持，不强行混装多个 `opencv-python` / `opencv-contrib-python` 变体。`pip freeze` 输出保存在自己的实验记录里；生成教材 PDF 的依赖是另一套，不需要为学习安装。

### L01｜数值、路径与异常（第 1–3 周）

**先会**：四则运算；按 [第一周行动单](first_week.md)运行程序。**输入**：[first_steps.py](examples/first_steps.py)及自己写的十行时间数据。

1. 完成第一周三次参数修改。第 2 周把 `frame_interval_ms` 的输入约束读懂，并自行写一个米转毫米函数；考虑零、负数和普通正数的含义。
2. 第 3 周建立 CSV：表头 `host_mono_ms`，数据先用 `0, 33, 67, 100, 133, 167, 200, 233, 267, 300`，每个值单独一行。这里是人为教学序列，不能称为相机实测。
3. 用标准库 `csv.DictReader` 读取数字，计算相邻差。把第 6 条改为 133（重复），第 7 条改为 120（倒序），输出异常所在数据行号。
4. 不静默删除异常，另存一份带诊断结果的文件。

**交付/通过**：原始与改动 CSV、程序、间隔表；能说明数据行号与包含表头的文件行号差一行。预备任务是手算十行差值；尚不能运行程序则 G1 仍未通过。

### L02｜数组、统计和图像（第 4–5 周）

**输入**：自己的非敏感照片，一组数 `[1,2,3,4,5]` 和 `[1,2,3,4,50]`。参考 R03、R04。

1. 计算两组数的均值、中位数和样本标准差（明确 `ddof=1`），解释离群值的影响；不要将样本标准差与总体标准差混写。
2. 使用 `cv2.imread`，先检查结果不是 `None`；打印 `shape` 和 `dtype`，说明宽高与通道。
3. 裁剪中央区域、用 `cv2.cvtColor` 转灰度、保存；展示时核对 BGR/RGB，避免颜色错位。
4. 改变一次裁剪范围，预测结果；用灰度直方图观察不同曝光照片。

**交付/通过**：原图与两张处理图、统计表、10 行以内自己的解释。失败先检查文件路径、读入结果和通道。没有摄像头不影响本实验。

### L03｜第一次图像采集（第 6 周，G1）

**输入**：已有或预算内的 USB 摄像头。参考 R04 的 Video Capture。

1. 使用 `cv2.VideoCapture` 打开设备，检查 `isOpened()`，记录请求与实际读到的尺寸。
2. 采集 60 秒。每次成功读取后用 `time.perf_counter_ns()` 记录主机单调时钟和程序帧序号；保存至少首、中、末三张图，避免初学阶段保存全部 RAW 占满磁盘。
3. 统计成功/失败读取次数、相邻返回间隔、中位数和最大间隔。实际交付帧率可用 `(成功帧数-1)/(末帧时间-首帧时间)`，不足两帧则无有效结果。
4. 报告中把字段命名为 `host_after_read_ns`，不能写成已知曝光时刻。正确释放设备。

**交付/通过**：日志、三张图、程序与解释；独立修改并预测一个参数的影响即满足 G1 的基础能力要求。没有设备可用图像序列完成 G1 的程序部分，但必须写“序列回放”，不得填写虚构采集帧率。

### L04｜坐标与投影纸笔实验（第 7–9 周）

**输入**：纸、笔、计算器和示例函数。参考基础手册第 5–6 节、R05。

1. 画 A、B 两个坐标系，为 `T_A_B` 写出方向；做 `(1,0)` 旋转和平移的两种次序。
2. 用逆变换把变换后的点还原，检查误差应在数值计算精度范围内。
3. 算出 `fx=600, cx=320, X=0.2` 时 `Z=1,2,4 m` 对应的 u 值：440、380、350 px。
4. 把相同模型整体缩小一半，讨论 fx、fy、cx、cy 如何随理想缩放变化；真实裁剪还会移动主点。

**交付/通过**：坐标图、正反变换表、投影表，能从单位检查出把毫米焦距当像素的错误。不会矩阵时先完成二维草图，再补 R05，不跳过变换方向。

### L05｜单相机标定与留出检查（第 10–12 周，G2）

**输入**：相机、[可打印棋盘](assets/checkerboard_8x5_20mm.pdf)、平整硬板、测量尺。参考 R07。

1. 打印选择“实际大小/100%”，关闭“适应页面”。核对横纵 100 mm 标尺，测多个连续格的总长度再除以格数；横纵比例不同或纸面弯曲时重做。对象点以实测米制格长创建。
2. 数清 **8×5 内角点 = 9×6 方格**。`findChessboardCorners` 的 patternSize 为 `(8,5)`；创建 40 个平面对象点，顺序与检测结果一致。
3. 采集约 20 张训练图、8 张留出图，覆盖中心/四角、不同距离和合理倾斜，棋盘完整清晰。固定分辨率与镜头设置，剔除原因写入清单，不凭结果好坏挑图。
4. 先检测角点、亚像素精化并画出序号；失败先检查格数、光照、运动模糊和边缘遮挡。用训练图执行 `calibrateCamera`，保存 K、畸变、尺寸、单位、模型和 OpenCV 版本。
5. 用 `projectPoints` 计算每图欧氏像素 RMS：`sqrt(mean(sum((observed-projected)**2, axis=1)))`。不能只报告一个总体数字。
6. 留出图不参与内参与畸变拟合；对每张用固定内参求棋盘姿态，再计算重投影误差，检查去畸变直线效果。这里的姿态仍从该图估计，所以称为留出一致性检查，不称绝对物理精度验证。

**通过标准**：流程可重跑；训练/留出名单独立；格长实测；参数齐全；逐图误差与异常解释齐全。可把“多数图约 1 px 内”作为普通清晰棋盘的初步排查目标，**不是所有相机的通用验收阈值**。误差大先查角点/模型/图像质量，不为过关调小记录值。无设备可先做官方样例；真实采集项保持待补。

### L06｜板载 IMU、单位与日志（第 13–15 周）

**输入**：XIAO nRF52840 Sense、数据线；参考 R08、R09。先运行官方示例，不先修改驱动。

1. 依官方说明安装板卡包与 LSM6DS3 库，选择正确板型和端口，上传 `HighLevelExample`；打开串口监视器。记录版本和波特率。
2. 平放、翻面、分别绕三轴缓慢转动。画出轴方向，对照变化；核对库实际输出单位，再换为 m/s² 与 rad/s。
3. 新建自己的例程副本，输出 `seq,device_read_us,ax_m_s2,ay_m_s2,az_m_s2,gx_rad_s,gy_rad_s,gz_rad_s`。`device_read_us` 表示软件读取事件，不等于精确采样时刻。
4. Python 串口接收每条完整记录后附加 `host_receive_ns`（单调时钟）。保存 60 秒静止数据和一段缓慢转动数据，记录串口设置、板卡重启和计数器回绕处理。
5. 区分配置的传感器输出数据率、寄存器轮询频率、串口发送频率。高级采样应查数据就绪/FIFO；没有新样本标志时不能把每次轮询当作独立新测量。

**交付/通过**：CSV、字段/单位/时钟说明、固件和接收脚本版本、轴向草图。初期只用 USB 和板载传感器，不要求焊接。串口不工作先换可传数据的线、确认端口未被其他程序占用。预备任务可用模拟六轴数据练单位，但不算真实 IMU 采集完成。

### L07｜噪声、时钟与记录诊断（第 16–18 周，G3）

**输入**：L06 数据，L03 时间戳。每个时钟域分开统计，不直接相减 MCU 时间和主机时间。

1. 选一段实际静止数据，算陀螺各轴均值/样本标准差、加速度模长。明确静止检测条件、温度是否记录、采样间隔。
2. 用实际相邻 dt 对一个轴做短时积分；比较减静止均值前后趋势。不能把“减均值”写成完成全部 IMU 标定。
3. 分别统计相机主机间隔、IMU 设备读数间隔、IMU 主机间隔。列出重复、倒序和超过中位间隔 2 倍的记录；该阈值只标记可疑间隔，没有硬件序号时不能证明传感器掉帧。
4. 画两条时间线，标出曝光、采样、读取、传输、主机收到。给每个未知延迟写“未知”，不要画成已精确对齐。
5. 让记录程序主动暂停约 0.2 秒再恢复，检查诊断能否发现变化；报告是软件暂停实验，不是传感器硬件失效。

**G3 通过**：真实六轴记录、静止统计、日志异常和时钟边界解释齐全。只有模拟数据则仍为预备。出现大漂移先查单位、dt、轴向和数据重复，再讨论模型。

### L08｜双目、匹配与静态标定（第 19–21 周）

**输入**：两台已分别标定并固定的相机，或 R07 双目教程链接的官方示例图。公开图示例优先，不强制买第二台相机。

1. 手算视差 30、15、5 px 的深度；再给视差加减 1 px，比较远距离误差为何更大。
2. 用 R04 的特征匹配示例匹配静态图像；保存重复纹理的错误例子，不只截取好看的匹配。
3. 真实双目路线：固定两相机，每对采集期间棋盘静止；多姿态记录相同角点。用单目内参作为初值并明确是否固定内参，执行 `stereoCalibrate`。
4. 为 R、T 标注方向和单位；调用 `stereoRectify` 与重映射，检查对应角点竖直坐标差。报告中展示至少一对留出图的校正前后结果。
5. 公开样例路线：从 R07 的官方代码/样例链接获取配套图像，记录来源与自带标定情况；只可声称复现了该样例，不声称标定过自己的两台相机。

**交付/通过**：视差表、匹配错误例、校正/深度结果及来源说明。静态成功不能证明动态同步。发现竖直差大先查点序、参数方向和相机是否移动。

### L09｜融合直觉与系统图（第 22–24 周，G4）

**输入**：静止/缓慢倾斜 IMU 数据，以及模拟直线点 `x=0..9, y=2x+1`。

1. 用加速度方向估计缓慢倾斜的趋势，和陀螺短时积分比较；快速平移一次，解释重力假设为何失效。无真实数据用明确标注的合成例子。
2. 把直线中一处 y 增加 20，最小二乘拟合两次，观察残差和参数；学习残差、权重、协方差的含义，不要求本周推导 EKF。
3. 画图像→特征/匹配→观测约束、IMU→传播→估计器→姿态/位置的系统图，标出内参、外参、时差、噪声配置的位置。
4. 口头解释 VO、VIO、SLAM 各需要什么和输出什么。

**G4 通过**：L08 静态双目或官方样例证据、变换方向和数据流图齐全；能说明六轴 IMU 的绝对偏航与位置限制。不会数学符号时先用箭头和语言解释，再补 R05/R06。

### L10｜已有 VIO 运行与评测（第 25–30 周，G5）

这是最可能超出原定周数的阶段。**本方案没有声称已在你的电脑上验证 OpenVINS 构建。** 参考 R11–R15，先核对实际版本再执行官方命令，不混用不同 ROS 发行版教程。

1. **第 25 周，环境审计**：写 OS/编译器/依赖/ROS/项目提交哈希矩阵。选择官方支持的隔离 Linux 环境；可以评估 ROS-free `run_simulation` 路径，但官方支持有限。保留构建命令和首个错误。
2. **第 26 周，数据审计**：只下载一个适合起步的数据序列，例如 EuRoC MH_01_easy，或准备官方模拟器配置。数据包格式要匹配所选接口；ROS-free 模拟器不是现成的 EuRoC 文件回放器。检查图像、IMU、参考轨迹、时间单位和配置文件来源。
3. **第 27 周，实际运行**：从当前项目提供的教程/示例配置开始，启动估计器并保存完整日志、轨迹与配置。不凭印象编造 launch 参数。模拟器路径要记录随机种子/噪声配置和模拟真值；数据集路径要记录下载来源及序列。
4. **第 28 周，评测**：依 evo 的实际 `--help` 将参考与估计轨迹转换成一致格式。例如 TUM 格式为 `timestamp tx ty tz qx qy qz qw`（秒、米、明确四元数约定）。保存时间关联参数和匹配样本数，分别计算 APE/RPE。VIO 优先 SE(3) 对齐，不能默默启用尺度校正。记录失败区间和完成比例。
5. **第 29–30 周，论文卡**：按资源导航各完成 VersaVIS、OpenVINS 一页读书卡，解释运行结果与论文环境的差异。只读理解当前实验所需部分。

**G5 正式通过**：实际运行已有 VIO 估计器（公开数据或官方模拟输入均可），有可追溯版本、日志、配置、输出轨迹、参考与评测；模拟结果明确标为模拟，不能作为真实硬件验证。

**阻塞时的预备任务**：用两条手工/模拟轨迹练时间匹配与误差计算，或分析来源明确的公开结果。至少画轨迹、解释对齐与单位、记录阻塞原因。此时 G5 不勾选；后续补实际运行。环境安装不能吞掉所有基础学习时间。

### L11｜结课项目：学习型采集与诊断台（第 31–35 周）

**输入**：前面已经掌握的设备、脚本和数据，不增加未知硬件。

1. 第 31 周写一页范围：要采什么、记录哪些时钟、有哪些已知校准、哪些未解决。选择自采单相机+IMU 诊断为主项目，VIO 仍用单独已验证的公开/模拟配置。
2. 第 32 周完成一次 10 分钟日志记录和抽样图像保存；保留帧序号、有效读取数、时间间隔统计、存储用量。若保存完整未压缩图像，先按基础手册估算空间。
3. 第 33 周独立重复两次标定或短时统计，比较变化。固定件移动后说明哪些外参可能失效，不把重复性当真值精度。
4. 第 34 周设计三个可恢复问题，例如遮挡镜头、弱光/模糊、软件读取暂停；每个都写现象、证据、判断、修复与复测。不要通过危险接线制造故障。
5. 第 35 周填 [报告模板](report_template.md)，按说明重新运行至少一个关键实验，录制两分钟讲解或保留等价带说明的图文演示。

**交付**：原始样本、配置、标定、诊断统计、版本和报告。自采相机+IMU 的时空关系未解决时，不强行输入 VIO 后把一条轨迹当作有效验证。

### L12｜验收与后续四周（第 36 周，G6）

1. 按 [进度表](progress.md)逐项打开 G1–G6 证据；没有证据就标未通过。
2. 闭卷解释一个坐标变换、一个 IMU 读数、一个时间戳和一项误差指标。
3. 选一个关键结果按报告重跑；比较差异并解释。
4. G6 项目交付通过需报告/原始数据/标定/诊断/复现步骤/边界说明齐全；整条学习路径完成还要求 G1–G5 均通过。

下一阶段只选一个重点：数学线（矩阵、概率、优化、滤波）、同步硬件线（触发/时钟与测量）、算法线（更完整的 OpenVINS/SLAM 复现）。先写四周任务和验收证据，再讨论额外预算。
